# Desk Money Controls Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the desk owner three controls FleetDesk lacks — mark a booking paid, override the price of an existing booking, and pick licence dates beyond 2031 — and back-port the "paid until" marker that currently exists only in the Little John fork.

**Architecture:** Three feature slices on one branch. Slice A (licence dates) is a pure-function bounds module consumed by both the public wizard's DatePicker and server-side `validateLicense`. Slice B (paid state) back-ports `bookings.paid_until` plus the planning-board unpaid flag from the Little John fork, fixes the `totalCents` key bug that has kept the amount-based branch dead, and adds a "Mark as paid" button on top of the existing `desk-payment` route. Slice C (price override) adds one owner-only route that rewrites `priceBreakdown.subtotalCents` while preserving the original quote and recording a signed `adjustmentCents` line, so the contract PDF still adds up.

**Tech Stack:** Next.js 15 (App Router), TypeScript, Drizzle ORM on Postgres (PGlite in tests), Zod, Vitest.

## Global Constraints

- Admin UI copy stays **English**. No i18n layer is introduced.
- Price override is **owner-only**. Mark-as-paid is available to owner and staff.
- The reason for a price change is **required, free text**, 3–500 characters after trim.
- Whatever the owner types is the revenue. No separate barter/settled payment method, no new `payment_method` enum value.
- No customer email is sent or re-sent by any change in this plan.
- Every admin mutation goes through `mutate(req, "admin.<action>", …)` from `src/lib/admin/guard.ts` so the audit row is automatic.
- Money is always integer cents. Never floats.
- `bookings.startAt` / `endAt` / `bufferEndAt` are `mode: "string"` timestamptz columns — pass ISO strings, not `Date` objects.
- Run the full suite with `npm test` (vitest, `pool: "forks"`). Typecheck with `npm run typecheck`.

```ts
/**
 * Selectable + accepted ranges for the three driver-licence dates.
 *
 * Shared deliberately by the public booking wizard (DatePicker derives its year
 * dropdown from min/max, so an unbounded field silently topped out at today + 5
 * years) and by server-side validateLicense. One source of truth means the
 * picker can never offer a date the server rejects, and no other caller can
 * push one past the server either.
 *
 * NOTE: zero imports. This module is pulled into a "use client" component, so
 * it must stay free of anything server-only.
 */

/** A driver older than this is assumed to be a typo, not a customer. */
export const LICENCE_DOB_MAX_AGE_YEARS = 100;
/** No real licence in circulation was issued longer ago than this. */
export const LICENCE_ISSUE_MAX_AGE_YEARS = 50;
/** Covers the long Aruban and Bonairian terms with room to spare. */
export const LICENCE_EXPIRY_MAX_YEARS_AHEAD = 25;

export interface DateBound { min: string; max: string }
export interface LicenceDateBounds {
  dob: DateBound;
  issueDate: DateBound;
  expiryDate: DateBound;
}

/** Shift a YYYY-MM-DD date by whole years, clamping 29 Feb to 28 Feb. */
export function shiftYearsISO(iso: string, years: number): string {
  const [y, m, d] = iso.split("-").map(Number) as [number, number, number];
  const targetYear = y + years;
  // Day 0 of month m (1-based) is the last day of month m - 1 in JS's 0-based
  // month indexing, i.e. the last day of the month we actually want.
  const daysInMonth = new Date(Date.UTC(targetYear, m, 0)).getUTCDate();
  const p = (n: number, w = 2) => String(n).padStart(w, "0");
  return `${p(targetYear, 4)}-${p(m)}-${p(Math.min(d, daysInMonth))}`;
}

export function licenceDateBounds(todayIso: string): LicenceDateBounds {
  return {
    dob: {
      min: shiftYearsISO(todayIso, -LICENCE_DOB_MAX_AGE_YEARS),
      max: todayIso,
    },
    issueDate: {
      min: shiftYearsISO(todayIso, -LICENCE_ISSUE_MAX_AGE_YEARS),
      max: todayIso,
    },
    expiryDate: {
      min: todayIso,
      max: shiftYearsISO(todayIso, LICENCE_EXPIRY_MAX_YEARS_AHEAD),
    },
  };
}
```

```ts
/**
 * Enforce the licence rules: each date must sit inside the same window the
 * booking wizard offers (license-bounds.ts), it must stay valid through the
 * return date, the driver must meet the minimum age at pick-up, and issue must
 * precede expiry.
 *
 * The bounds are checked here and not only in the picker because the picker is
 * a convenience; this is the gate. Without it the server happily accepted a
 * 2030 date of birth and printed it on the rental contract.
 */
export function validateLicense(
  license: LicenseInput,
  ctx: { minDriverAge: number; rentalStart: string; rentalEnd: string; today: string },
): void {
  const bounds = licenceDateBounds(ctx.today);
  if (license.dob > bounds.dob.max || license.dob < bounds.dob.min) {
    throw Errors.badRequest("Please check the date of birth");
  }
  if (license.issueDate > bounds.issueDate.max || license.issueDate < bounds.issueDate.min) {
    throw Errors.badRequest("Please check the licence issue date");
  }
  if (license.expiryDate > bounds.expiryDate.max) {
    throw Errors.badRequest("Please check the licence expiry date");
  }
  if (license.issueDate >= license.expiryDate) {
    throw Errors.badRequest("Licence issue date must be before its expiry date");
  }
  if (license.expiryDate <= ctx.rentalEnd) {
    throw Errors.badRequest("Licence must stay valid through the return date");
  }
  const age = ageOn(license.dob, ctx.rentalStart);
  if (age < ctx.minDriverAge) {
    throw Errors.badRequest(`Driver must be at least ${ctx.minDriverAge} years old`);
  }
}
```

```ts
import { withRoute } from "@/lib/http/handler";
import { json } from "@/lib/http/respond";
import { parseParams, parseJsonBody } from "@/lib/http/validate";
import { mutate } from "@/lib/admin/guard";
import { getDb } from "@/lib/db/client";
import { bookings } from "@/lib/db/schema";
import { Errors } from "@/lib/http/errors";

export const runtime = "nodejs";
export const dynamic = "force-dynamic";

const ParamsSchema = z.object({ id: z.string().uuid() });
const BodySchema = z.object({
  // "Betaald t/m": how far the renter has paid on a monthly rental. null clears
  // the marker and the board falls back to the amount-based unpaid flag.
  paidUntil: z.string().regex(/^\d{4}-\d{2}-\d{2}$/, "must be YYYY-MM-DD").nullable(),
}).strict();

/** POST /api/admin/bookings/:id/paid-until — set or clear the paid-until
 *  marker on an active rental. Pure marker: the payments ledger is untouched. */
export const POST = withRoute(async (req, { params }) => {
  const { id } = parseParams(await params, ParamsSchema);
  const { paidUntil } = await parseJsonBody(req, BodySchema);
  const updated = await mutate(req, "admin.paid_until_set", async () => {
    const db = await getDb();
    const [booking] = await db.select().from(bookings).where(eq(bookings.id, id));
    if (!booking) throw Errors.notFound("Booking not found");
    if (booking.status === "cancelled") throw Errors.conflict("This booking is cancelled");
    const [row] = await db.update(bookings)
      .set({ paidUntil, updatedAt: new Date() })
      .where(eq(bookings.id, id))
      .returning();
    return { result: row!, entity: "booking", entityId: id, after: { paidUntil } };
  });
  return json({ id: updated.id, paidUntil: updated.paidUntil }, req);
});
```

Create `src/lib/admin/paid-state.ts`:

```ts
/**
 * Is there money outstanding on this rental, and why?
 *
 * Two mechanisms feed one answer, deliberately kept side by side:
 *
 *   - "Betaald t/m" (paidUntil) — a coverage marker the desk maintains on
 *     rolling monthly rentals. It touches no money; it says which day the
 *     renter has paid through. When it is set, it decides.
 *   - The balance — snapshot subtotal minus everything actually settled.
 *     Used for ordinary day rentals, and whenever no marker is set.
 *
 * Only a rental that has actually gone out can be "unpaid" on the board:
 * picked_up (with the customer) or completed (back, but never settled). A
 * pending or confirmed booking is simply not owed yet, and a cancelled one is
 * not owed at all.
 *
 * This lives in its own module, with zero imports, so the rule is unit-testable
 * on its own. The Little John fork inlined it inside the planning query, and
 * that is exactly how a typo (`totalCents`, a key nothing ever writes) survived
 * in production long enough to keep the balance branch permanently dead.
 */

export interface PaidStateInput {
  status: string;
  paidUntil: string | null;
  subtotalCents: number;
  amountPaidCents: number;
  currency: string;
  /** Today in the operator's local timezone, YYYY-MM-DD. */
  todayLocal: string;
}

export interface PaidState {
  unpaid: boolean;
  balanceDueCents: number;
  /** One plain sentence for the board tooltip and the drawer, or null. */
  note: string | null;
}

const OUT_OR_DONE = new Set(["picked_up", "completed"]);

function money(cents: number, currency: string): string {
  const amount = (cents / 100).toFixed(2);
  return currency === "USD" ? `$${amount}` : `${currency} ${amount}`;
}

export function paidState(i: PaidStateInput): PaidState {
  const balanceDueCents = Math.max(0, i.subtotalCents - i.amountPaidCents);
  const live = OUT_OR_DONE.has(i.status);

  // "t/m" is inclusive: a marker of the 8th means the 8th is still covered.
  const unpaid = live && (i.paidUntil !== null
    ? i.paidUntil < i.todayLocal
    : balanceDueCents > 0);

  let note: string | null = null;
  if (unpaid && i.paidUntil !== null) note = `Unpaid: paid until ${i.paidUntil}`;
  else if (unpaid) note = `Unpaid: ${money(balanceDueCents, i.currency)} still due`;
  else if (i.paidUntil !== null) note = `Paid until ${i.paidUntil}`;

  return { unpaid, balanceDueCents, note };
}
```

```ts
/**
 * Owner price override on an existing booking.
 *
 * The owner sometimes settles a rental against something else, or corrects a
 * price after the fact. Whatever is typed becomes the revenue — reports read
 * subtotalCents and follow automatically.
 *
 * The override deliberately PRESERVES the original quote rather than replacing
 * it. The rental-contract PDF itemises the breakdown line by line (vehicle,
 * insurance, add-ons, young-driver fee), so flattening it to a bare amount
 * would print a contract whose lines do not add up to its total. Instead the
 * original lines stay, subtotalCents is rewritten, and a signed adjustmentCents
 * carries the difference as its own line.
 *
 * NOTE: zero imports, so the shape is unit-testable without a database.
 */

export interface PriceOverrideMeta {
  /** The subtotal the ORIGINAL quote produced, never the previous edit. */
  previousSubtotalCents: number;
  reason: string;
  byAdminId: string;
  /** ISO timestamp. */
  at: string;
}

/**
 * priceBreakdown is untyped jsonb and comes in two shapes — a full
 * QuoteBreakdown for online bookings, a flat {manual, subtotalCents, currency}
 * for desk-created ones — so everything here is optional and passthrough.
 */
export interface OverridableBreakdown {
  subtotalCents?: number;
  adjustmentCents?: number;
  priceOverride?: PriceOverrideMeta;
  [key: string]: unknown;
}

/** The quoted subtotal, looking through any override already applied. */
export function originalSubtotalCents(breakdown: OverridableBreakdown): number {
  return breakdown.priceOverride?.previousSubtotalCents ?? Number(breakdown.subtotalCents ?? 0);
}

export function applyPriceOverride(
  breakdown: OverridableBreakdown,
  newSubtotalCents: number,
  meta: { reason: string; byAdminId: string; at: string },
): OverridableBreakdown {
  // Anchor on the ORIGINAL quote so a second edit does not measure itself
  // against the first one; otherwise the adjustment line drifts and the
  // contract's line items stop summing to the total.
  const original = originalSubtotalCents(breakdown);
  return {
    ...breakdown,
    subtotalCents: newSubtotalCents,
    adjustmentCents: newSubtotalCents - original,
    priceOverride: { previousSubtotalCents: original, ...meta },
  };
}
```

```ts
/**
 * Owner price override on an existing booking (design 2026-09-08 §3).
 *
 * The desk sometimes settles a rental against something else, or has to correct
 * a price after the fact. Whatever the owner types becomes the revenue: the
 * reports read priceBreakdown.subtotalCents and follow automatically.
 *
 * Owner-only, mirroring the money gate on extend-booking.ts:69-71 — a desk
 * price change moves real money in the books, and the audit row (with the
 * mandatory reason) is what replaces a second pair of eyes.
 */
import { and, eq } from "drizzle-orm";
import { getDb } from "@/lib/db/client";
import { bookings, payments } from "@/lib/db/schema";
import { Errors } from "@/lib/http/errors";
import { applyPriceOverride, type OverridableBreakdown } from "@/lib/booking/price-override";
import type { BookingRow } from "@/lib/admin/inspections";
import type { AdminRole } from "@/lib/auth/admin-auth";

export interface SetPriceInput {
  subtotalCents: number;
  reason: string;
  adminId: string;
  role: AdminRole;
}

export interface SetPriceResult {
  booking: BookingRow;
  /** The subtotal immediately before THIS edit — what the audit row records. */
  previousSubtotalCents: number;
  newSubtotalCents: number;
}

export async function setBookingPrice(
  bookingId: string,
  input: SetPriceInput,
): Promise<SetPriceResult> {
  if (input.role !== "owner") {
    throw Errors.forbidden("Only an owner can change the price of a booking");
  }
  if (!Number.isInteger(input.subtotalCents)) {
    throw Errors.badRequest("Price must be a whole number of cents");
  }
  if (input.subtotalCents < 0) {
    throw Errors.badRequest("Price cannot be negative");
  }
  const reason = input.reason.trim();
  if (reason.length < 3) {
    throw Errors.badRequest("Please give a short reason for the price change");
  }
  if (reason.length > 500) {
    throw Errors.badRequest("Please keep the reason under 500 characters");
  }

  const db = await getDb();
  return db.transaction(async (tx) => {
    const [booking] = await tx.select().from(bookings).where(eq(bookings.id, bookingId)).for("update");
    if (!booking) throw Errors.notFound("Booking not found");
    if (booking.status === "cancelled") {
      throw Errors.conflict("This booking is cancelled, its price can no longer change");
    }
    if (input.subtotalCents < booking.amountPaidCents) {
      throw Errors.badRequest(
        "That is less than has already been paid on this booking. Record a refund first.",
      );
    }

    // An open checkout session was priced from this snapshot and the webhook
    // re-checks the expected amount against it when the money lands. Editing in
    // between silently desyncs Stripe from the booking.
    const [open] = await tx.select({ id: payments.id }).from(payments)
      .where(and(eq(payments.bookingId, bookingId), eq(payments.status, "pending")));
    if (open) {
      throw Errors.conflict("A payment is still open on this booking. Wait for it to settle or fail first.");
    }

    const previous = booking.priceBreakdown as OverridableBreakdown;
    const previousSubtotalCents = Number(previous.subtotalCents ?? 0);
    const next = applyPriceOverride(previous, input.subtotalCents, {
      reason,
      byAdminId: input.adminId,
      at: new Date().toISOString(),
    });

    const [updated] = await tx.update(bookings)
      .set({ priceBreakdown: next, updatedAt: new Date() })
      .where(eq(bookings.id, bookingId))
      .returning();

    return { booking: updated!, previousSubtotalCents, newSubtotalCents: input.subtotalCents };
  });
}
```

```ts
import { json } from "@/lib/http/respond";

import { mutate } from "@/lib/admin/guard";

export const dynamic = "force-dynamic";

const ParamsSchema = z.object({ id: z.string().uuid() });
const BodySchema = z.object({
  subtotalCents: z.number().int().min(0).max(5_000_000),
  // Required on purpose: six months later the audit row is the only place that
  // remembers why a rental was $80 cheaper.
  reason: z.string().trim().min(3).max(500),

/** PATCH /api/admin/bookings/:id/price — owner-only price override. The
 *  original quote is preserved and the difference is recorded as a signed
 *  adjustment line, so the rental contract still itemises and still adds up. */
export const PATCH = withRoute(async (req, { params }) => {
  const { id } = parseParams(await params, ParamsSchema);
  const body = await parseJsonBody(req, BodySchema);

  const result = await mutate(req, "admin.booking_price_changed", async (ctx) => {
    const r = await setBookingPrice(id, {
      subtotalCents: body.subtotalCents,
      reason: body.reason,
      adminId: ctx.admin.id,
      role: ctx.admin.role,
    });
    return {
      result: r,
      entity: "booking",
      entityId: id,
      before: { subtotalCents: r.previousSubtotalCents },
      after: { subtotalCents: r.newSubtotalCents, reason: body.reason.trim() },
    };
  }, { roles: ["owner"] });

  const bd = result.booking.priceBreakdown as { subtotalCents?: number; adjustmentCents?: number };
  return json({ id: result.booking.id, subtotalCents: bd.subtotalCents, adjustmentCents: bd.adjustmentCents }, req);
});
```
